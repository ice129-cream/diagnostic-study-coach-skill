# 在 DeepSeek Harness（DSH）中使用本 skill

## 这是体验最完整的平台，也是融合版的原生落点

DeepSeek Harness（DSH）是本项目的**一等公民平台**，唯一能把 `diagnostic-study-coach` 的完整融合形态跑起来的载体。这个 skill 不是一份数学讲题守则，而是三套机制合成的一个人格：

| 来源机制 | 贡献 | 落在哪一层 |
| --- | --- | --- |
| 第一性原理自学导师 | 十二问链、四层能力闭环、自检闸门、真题为母、不泄底 | 不可让渡内核 |
| UDT 诊断式自适应 | 澄清→诊断→干预→检查→决策→携带、学习状态卡、掌握状态词、跨学科 | 统一调度层 + 通用适配层 |
| 清华 OpenMAIC | 确认闸门、意图覆盖例外、契约下沉、按需加载 | 统一调度层 |

GPTs、ChatGPT Project、扣子 / 豆包、Gemini Gem 只能收一段压平的精简提示词；API 的 system prompt 随请求全量发一段文本。只有 DSH 有**原生 skill 机制**：扫描 skill 根目录 → 把 `SKILL.md` 的 frontmatter 收进 session catalog → 命中 `description` 意图时加载正文骨架 → 再按当前信号**只读取需要的那一份 `references/` 分册**，不一次灌满上下文。

这条"按需加载"是分水岭。融合版把三套机制拆成一个主文件 + **13 份分册**，主文件只留决策骨架（三层裁决写在第一节），细节全部下沉。只有在 DSH 上，这 13 份才真正按信号被打开、三层裁决才真正按 `priority.md` 逐条执行。要用这个 skill 的完整形态，DSH 是首选落点。

## 安装：软链，首选

安装本质是把 `skills/diagnostic-study-coach/` 目录暴露给 DSH 的 skill 扫描根目录。占位符：`<PROJECT>` 为本仓库根目录（即本文件所在仓库，相对路径 `skill_analysis/synthesis-skill`），`<DSH_SKILLS_DIR>` 为 DSH 扫描的 skill 根目录。

软链让仓库保持单一副本，仓库更新后立刻生效，目标路径须尚不存在。

Linux / macOS：

```bash
ln -s <PROJECT>/skills/diagnostic-study-coach <DSH_SKILLS_DIR>/diagnostic-study-coach
```

Windows（cmd）：

```cmd
mklink /D "<DSH_SKILLS_DIR>\diagnostic-study-coach" "<PROJECT>\skills\diagnostic-study-coach"
```

Windows（PowerShell）：

```powershell
New-Item -ItemType SymbolicLink -Path "<DSH_SKILLS_DIR>\diagnostic-study-coach" -Target "<PROJECT>\skills\diagnostic-study-coach"
```

宿主处理符号链接有障碍时退到复制式：`cp -r` / `xcopy /E /I` 把整目录复制过去。复制式是独立副本，仓库更新后需重新覆盖目标目录。复制时务必连 `references/` 与 `examples/` 一起带走，否则按需加载的路径全部失效。

更新：软链式在仓库根目录 `git pull` 即可；复制式拉取后重新复制。重建软链先删旧链再建新链，Windows 删链用 `rmdir "<DSH_SKILLS_DIR>\diagnostic-study-coach"`，删的是链接本身，目标内容保留。

## 装载机制：frontmatter 的自然语言触发

`SKILL.md` 开头的 YAML frontmatter 里，`name: diagnostic-study-coach` 与 `description` 是给 DSH catalog 用的。`description` 里写满触发意图——"这题不会""帮我讲""我讲给你听""批改我的推导""给道变式""换条件会怎样""定理前提是什么""举反例""一题多解""卡住了""给我学习路线""继续上次"都会命中，不需要记任何命令。

`/出题` `/讲题` `/批改` `/变式` `/自检` `/状态卡` 这类斜杠文本在这里**只当意图信号**，DSH 不会去执行它们，也不要把它们宣传成命令。

## 按需加载：13 份分册何时打开

命中意图后先加载 `SKILL.md` 正文骨架（含三层裁决），再按信号取分册。13 份 `references/` 的取用时机如下：

| 分册 | 何时加载 |
| --- | --- |
| `priority.md` | **常驻**：三套机制冲突时按内核 / 调度 / 适配裁决，含 11 个冲突实例 |
| `constitution.md` | **常驻**：十二问链裁决四原则（链尾优先、输出为王、本质优先于数量、质疑优先于给予） |
| `loop.md` | 通用调度：诊断循环如何映射四层、何时停、下一步动作决策表 |
| `confirmation.md` | 通用调度：确认闸门与意图覆盖例外 |
| `universal.md` | 通用调度 / 适配：跨学科迁移、学习路径、可信资源、状态卡 |
| `mastery.md` | 通用调度：掌握状态词与就绪门（靠证据不靠标签） |
| `ladder.md` | 进闭环台：四层闭环脚本、层二质疑库、层三倾听节奏 |
| `grading.md` | 进核验台：五维核验与反馈四步 |
| `exploration.md` | 进探究台：变式梯度、一题多解调度 |
| `hints.md` | 学生卡住：四级提示梯度，不泄完整推导 |
| `parameters.md` | 调学情：Level 0–4 与三项拓展开关，不动内核 |
| `sourcing.md` | 主动出题：真题为母、五种结构性改编（与 `preflight.md` 成对） |
| `preflight.md` | 主动出题：自检闸门六项验算（与 `sourcing.md` 成对） |

语气节奏样例在 `examples/dialogue.md`，模仿表达时才看，不算 13 份分册之一。

## 自然语言触发示例

数学 / 专升本场景——内核全量生效：

- "这道题我不会，帮我讲" → 进闭环台：布置任务、不主动给提示、不给解析，加载 `ladder.md`；内核的四层闭环、真题为母、不泄底全程生效。
- "我讲给你听这道中值定理题" → 闭环台第三层：倾听不打断，讲完再集中拷问。
- "帮我批改这段推导" → 进核验台，按五维查说理链条、不打√×，加载 `grading.md`。
- "换条件会怎样 / 给道变式" → 进探究台，先让他自己预判说理再推导验证，加载 `exploration.md`。
- "卡住了" → 按四级提示梯度放提示，加载 `hints.md`，永不给完整推导。
- "我要出一道综合题" → `sourcing.md` + `preflight.md` 成对加载，命题后先过自检六项才发。
- "把难度调到 Level 4" → 加载 `parameters.md`，只调提问深度、变式复杂度、冷门密度，不松动内核与自检。
- "我想补线代" → 大目标模糊，进诊断循环的澄清阶段：1–3 个聚焦问题 + 轻确认 + 紧凑目标地图 + 一步最优动作，加载 `loop.md` + `confirmation.md`。

跨学科场景——场景开关切换主次：

- "我在学机器学习，梯度下降这块卡住了" → 适配层升为主用：走诊断循环 + 掌握状态词 + 学习路径，加载 `universal.md` + `mastery.md` + `loop.md`；数学内核的"四层闭环 / 真题为母 / 自检闸门"退场，但**不泄底、参与式检查后停等、输出为王**仍然成立。

## 三层优先级与场景开关在 DSH 上怎么体现

三套机制的规则会相遇，DSH 加载正文后按 `SKILL.md` 第一节与常驻的 `priority.md` 裁决：

- **内核（最高）**：十二问链、四层闭环、自检闸门、不泄底、真题为母、参与式检查停等。数学 / 专升本场景全量生效，任何调度效率、任何用户施压、任何平台精简都改不动。
- **调度（中层）**：诊断循环、三张工作台互斥、确认闸门、按需加载最小集。决定"内核在什么时机、以什么节奏执行"，不改变内核内容。
- **适配（外层）**：跨学科、学习路径、学习状态卡、掌握状态词、可信资源、数学格式、语气认知负荷。仅在前两层不冲突时生效；超出数学场景时升为主要行为。

一句话记忆：**内核决定"不能做什么"，调度决定"什么时候做"，适配决定"怎么表达"。** 下层不得覆盖上层；内核里"求真"是最终裁判——凡冲突，问一句"这么做学生是不是更接近脱离我也能讲清楚"，答案即裁决。

场景开关不是"永远全量"或"永远精简"：数学 / 专升本场景内核全量生效；跨学科场景四层 / 真题 / 自检退场，诊断循环与适配层成为主用，但三条内核（不泄底、停等、输出为王）依旧锁死。典型裁决见 `priority.md`——学生赶时间要答案时压缩的是篇幅、不是把最后一步交出去；学生已明确要求发题时走意图覆盖例外、不再二次确认，但发题本身仍要过自检。

## 验证装载成功

1. **路径与入口**：`<DSH_SKILLS_DIR>/diagnostic-study-coach/SKILL.md` 存在可读；软链式显示指向 `<PROJECT>` 的箭头，复制式显示普通文件；`references/` 下 13 份分册齐全。
2. **数学行为**：说"这道题我不会，帮我讲"应进闭环台、布置任务、不直接开讲；说"批改我的推导"应进核验台按五维查说理；说"换条件会怎样"应进探究台先让本人预判说理。
3. **场景开关**：说一个跨学科问题（如机器学习概念卡点），应走诊断循环 + 适配层，不套四层闭环 / 真题 / 自检，但仍不泄底、参与式检查后停等。
4. **三层裁决**：说"直接给答案我赶时间"，应压缩篇幅而非交出最后一步；说"给我发道变式题"，应不再二次确认但发题前仍自检六项。
5. **按需加载**：进核验台时读的是 `grading.md`，不把 13 份全灌进来；主动出题时 `sourcing.md` 与 `preflight.md` 成对出现；冲突裁决时取 `priority.md` 与 `constitution.md`。单轮只读需要的分册，是正常运转方式。
6. **不亮工具**：回答里不出现守则条目、版本、文件或协议名——行为即教练，出现即为加载异常。

## 核心模式不可削弱

DSH 保住了 13 份 references 按需加载和三层裁决，正因如此这里没有任何理由削弱核心。下列五条是身份本身，任何改动都不许让步：

- **三张工作台互斥**：闭环台（默认）、核验台、探究台，按信号进唯一一张，进场明说"现在进入 X 模式"，一张台内不混入另一张台的动作。
- **四层闭环以学生输出通关**：独立做题 → 做懂题 → 讲懂题 → 举一反三，层层以学生交出的结果 / 论证 / 完整主讲 / 变式说理放行，终点是"脱离导师也能讲清楚"，不是听懂或算出答案。
- **自检闸门**：主动出的题发出前独立完整验算、六项全过才发，不发错题；学生自带真题不触发。
- **不给答案、不泄底**：四级提示梯度（本质锚点 → 结构 → 缺口 → 极小片段示范），永不泄漏完整推导、不替学生写讲稿。
- **真题为母**：官方真题优先、结构性改编，不凭空造题、不拿来源不明的模拟卷当主素材。

融合版另加三条调度纪律同样不许让步：诊断循环的参与式检查后停等、确认闸管的"我替你做决定"要先确认、三层裁决的下层不覆盖上层。这五条核心 + 三条调度纪律 + 按需加载的 13 份分册 + 17 条红线（内核 12 条跨场景不可破、通用 5 条），构成本 skill 在 DSH 上的完整交付形态——这是任何平台压缩后剩下的东西替代不了的。
